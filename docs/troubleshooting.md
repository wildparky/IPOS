# 문제 해결과 검증 범위

| 증상 | 확인 및 대응 |
|---|---|
| 내부 IP에서 검은 화면 | HTML 200만으로 렌더링 성공을 판단하지 마세요. Console 오류와 UUID 호환 버전을 확인하고 강력 새로고침합니다. |
| 내장 브라우저의 기존 탭만 검은 화면 | 동일 주소의 새 탭에서 먼저 확인합니다. 기존 탭 이동이 ERR_ABORTED로 중단될 수 있으며, 이것만으로 앱 오류를 확정할 수 없습니다. 서버 프로젝트는 유지되지만 미저장 초안은 탭을 닫기 전에 확인해야 합니다. |
| 프로젝트 저장 충돌 | 다른 클라이언트 저장 여부 확인 → 복구본 내보내기 → 최신 프로젝트 로드. 무조건 덮어쓰지 않습니다. |
| 상대 변경이 바로 보이지 않음 | 열린 캔버스는 3초 간격으로 조회합니다. 저장 대기·충돌 상태에서는 원격 내용으로 로컬 초안을 덮어쓰지 않습니다. 양쪽 모두 최신 코드로 새로고침했는지 확인하세요. |
| 이미지가 보이지만 저장 실패 | 화면 미리보기와 서버 저장은 별개입니다. 저장 오류를 확인하고 탭을 닫기 전 복구본을 보관합니다. |
| This mode requires one image | 선택한 inputMode와 전송된 이미지 개수 확인. Omni 요청이 singleImage로 떨어졌는지 확인합니다. |
| TopView code 4000 | task ID와 제출 단계를 확인합니다. 모델·mode·참조 토큰·실제 schema를 대조하고 상세 원인을 추측으로 단정하지 않습니다. |
| 생성 완료 후 import 실패 | 기존 task/result를 보존하여 복구합니다. 새 유료 생성으로 자동 재시도하지 않습니다. |
| MCP 도구 미노출 | 공식 CLI 버전·app-server 지원·MCP 등록·OAuth 확인. probe 실행. |
| Serve not enabled | CLI가 제시하는 해당 기기의 관리 승인 링크를 사용합니다. status와 실제 HTTPS API 응답으로 확인합니다. |
| 미디어 후보 0개 | 백업/프로젝트/현재 브라우저 컬렉션 참조 또는 30일 유예기간 보호일 수 있습니다. |

## fb6ff30 검증 기록

- build 성공. 500KB 초과 번들 경고는 남아 있습니다.
- 테스트 30개 중 29개 통과, Windows symlink 권한 제한으로 1개 건너뜀.
- 단위 테스트는 revision, 저장, 미디어 분리, 조회, UUID fallback 등을 다룹니다.
- 개발 환경에서 Text/Image to Video의 결과 import와 Omni Reference 제출이 확인됐습니다.
- 모든 모델·모드 조합의 실제 유료 생성, 원격 다중 사용자 공동 편집을 검증했다는 의미는 아닙니다.
- 프로젝트/미디어 데이터와 OAuth 자격증명은 Git 저장 대상이 아닙니다.

실제 테스트 개수는 이후 커밋에서 바뀔 수 있으므로 npm test의 최신 출력을 우선하세요.
